# Linux 系统管理

Linux 首页提供服务、进程、软件包、网络和磁盘五个独立入口。Tundra 以普通用户运行；需要系统权限的操作会在 Tundra 内询问 sudo 密码，再由独立助手执行固定操作。`tundra-cli` 需要与 `tundra-shell` 放在同一目录。

## 使用方式

| 按键 | 行为 |
| --- | --- |
| `/` | 输入搜索内容，Enter 应用，Esc 结束输入 |
| ↑ / ↓、PgUp / PgDn | 移动列表或操作选择 |
| Enter | 查看选中行的详情；焦点在操作区时执行选中操作 |
| Tab / Shift+Tab | 在列表与操作区之间切换 |
| `R` | 重新读取当前列表；软件包的“刷新源”另行下载仓库信息 |
| Ctrl+T | 打开或关闭内嵌终端 |
| Esc | 返回；表单中取消当前表单 |

表单中用 Tab 或 ↑ / ↓ 移动，← / → 切换选项，Ctrl+U 清空当前文本字段。Enter 移动到下一项；选中提交项后按 Enter 提交。PgUp / PgDn 滚动说明，可查看较长的依赖和配置提示。

内嵌终端显示正在运行的命令输出，也能回答特殊安装脚本的问题。Shift+PgUp / Shift+PgDn 或鼠标滚轮查看历史；普通方向键发给正在运行的程序。原生确认表单出现时，可用 Ctrl+T 查看输出，再切回表单回答。

## 支持范围

| 入口 | 可执行操作 | 条件与限制 |
| --- | --- | --- |
| 服务 | 系统/当前用户服务列表、详情、启动、停止、重启、开机启用/禁用、日志 | 使用 systemd；用户服务需要可用的用户会话。只管理 `.service`，日志受当前用户权限限制 |
| 进程 | 搜索、排序、进程树、详情、正常终止、强制终止、暂停、继续、调整主线程优先级 | 读取 `/proc`；发送信号需要 Linux 的 pidfd 支持。操作前重新核对进程，保护 PID 1 和管理进程 |
| 软件包 | 搜索、详情、已安装/可更新列表、刷新源、安装、普通卸载、单项/全部升级 | Ubuntu/Debian 使用 APT/dpkg，Fedora 使用 DNF 4 或 DNF 5；不要求 PackageKit。支持有这些命令的精简服务器 |
| 网络 | 接口与连接详情、IPv4/IPv6、DHCP/静态地址、网关、DNS；个人 Wi-Fi 连接、断开、忘记已保存配置 | 识别 NetworkManager、Netplan、systemd-networkd 或 Debian interfaces。只修改能确定归属的配置；Wi-Fi 操作要求 NetworkManager |
| 磁盘 | 设备与挂载点、容量/可用空间、文件系统详情、只读/读写挂载、卸载、打开目录、目录占用与大文件扫描 | 优先 UDisks2，也支持固定 `mount`/`umount` 操作；不提供格式化、分区、解锁或 fstab 编辑。扫描保留用户权限，跳过符号链接和其他挂载点 |

缺少系统工具、服务未运行或配置归属不明确时，界面会显示原因。程序不会为此自动安装系统组件。

## 软件包确认与失败处理

搜索和列表使用已有仓库信息；需要最新信息时选择“刷新源”。搜索最多显示 2,000 行，更多结果请缩小搜索范围。更新列表来自只读查询，不会据此自动批准后续安装。

执行前重新核对已安装版本，以及界面曾展示的仓库候选版本；版本已经变化时，须刷新列表再确认。实际运行的 APT 或 DNF 会重新计算依赖。APT 可能直接执行已明确指定且没有额外依赖的单包操作，这种情况只有 Tundra 的操作确认，不宣称每次都有原生二次确认。常见依赖确认和 dpkg 配置冲突在表单中回答；特殊安装脚本使用内嵌终端。过长的计划会要求在终端中检查实际输出并回答，避免把截断内容当作完整计划。

普通卸载保留配置，不自动执行 purge 或 autoremove。DNF 不自动清理不再使用的依赖。RPM 配置变化可能留下 `.rpmnew` 或 `.rpmsave`，请根据输出检查这些文件。软件包升级不是完整系统发行版升级。

进入修改阶段后，关闭页面或退出 Tundra 不会强杀软件包管理器。安装终端会过滤 Ctrl+C、Ctrl+D、Ctrl+Z 和 Ctrl+\\，以免中断修改。失败可能已经改变部分软件包；界面会显示真实退出结果，需要根据输出处理，不承诺自动恢复整个软件包事务。

## 后台任务与网络回退

系统操作由独立助手保留，Tundra 只是连接到它的界面。离开页面后操作继续；重新启动 Tundra 后，在操作区选择“重新连接系统任务”，选择要连接的任务。不要在结果未知时重复提交同一操作。

重新连接可以接收仍在等待的问题和保留的输出。历史输出有大小限制，完成结果保留约十分钟；这不是永久日志。机器重启或助手被外部终止后，不能恢复原来的运行进程。

网络修改先准备备份和独立恢复任务，再暂时应用配置。应用后须在 120 秒内选择保留；选择恢复、超时或界面断开且没有确认时，恢复任务会尝试恢复原配置。配置被其他程序同时改动时会报告冲突，不能保证任何外部改动下都能恢复。缺少所需恢复工具时不执行修改。

## 验证范围

开发时使用本机 WSL Ubuntu 运行 Linux 检查。软件包自动测试覆盖查询解析、固定操作参数、输入限制，以及真实 PTY 的确认、断开等待、脚本交互和失败结果。另有显式只读 APT 检查，读取已安装、搜索、详情和可更新列表，不执行安装或刷新源。

运行软件包检查：

```sh
cargo test --locked -p platform management::packages --lib
cargo test --locked -p platform management::packages::query::tests::live_apt_installed_search_updates_and_details --lib -- --ignored
```

完整仓库检查使用 `cargo test --workspace --locked`。测试通过不代表真实 Fedora、Wi-Fi、物理磁盘挂载或系统软件包写入已验收；这些还需要在对应机器或可恢复的测试环境中验证。

下一批可补充：防火墙、SSH/远程连接、定时任务、备份恢复、容器管理。
