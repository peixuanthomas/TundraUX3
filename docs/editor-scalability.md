# Source 编辑器的大文件计算

这次修改移除了搜索的全文件字素偏移数组，并把高亮、软换行、搜索和行变更标记的大文件重计算移出主事件循环。原实现对 10 MiB 无换行 ASCII 文本需要至少约 80 MiB 的 `usize` 边界元素空间，尚未计入 `Vec` 容量、全文字符串和匹配结果。

## 计算与缓存

- **LSH**：视口只保留所需逻辑行的 token；每 128 行保存一次解析状态，最多保留 2,048 个检查点。编辑使受影响行及其后的检查点失效，前缀仍可复用。初次跳到文件末尾时，仍需在后台解析前缀，以保留多行注释和字符串的正确状态。
- **软换行**：后台建立每个逻辑行的累计显示行数，显示行按需生成。ASCII 行的位置直接计算；长 Unicode 行每 256 个显示行保存一个字节检查点。编辑只重算受影响逻辑行，随后在后台调整行数索引；改变宽度需要重建索引。索引内存仍与逻辑行数量成正比。
- **搜索**：普通文本查询以 64 KiB 窗口加查询长度及 Unicode 单词边界上下文扫描 Rope，匹配端点用字素游标验证。可处理跨块匹配、组合字符、ZWJ Emoji、国旗及 CRLF。交互搜索保留最多 512 个匹配位置，完整计数不截断；F3 在页内复用结果，跨页重新扫描并保留下一页。搜索着色对应当前缓存页。
- **替换**：预览由同一分块引擎执行，保留修订号和文档代次检查；应用前重新校验原文、范围与字素边界，仍为一次 Undo。全量预览最多保留 10,000 处匹配或 8 MiB 的文本及条目数据，超限明确报错，绝不应用部分结果。“当前匹配”不受全量匹配数量限制。
- **后台任务**：文件超过 64 KiB 时使用后台线程；每个功能最多有一个运行任务和一个可被覆盖的待处理任务。新请求取消旧请求，过期结果不能回写。Shell 在结果到达时重绘，软换行计算期间继续显示可操作的原始行。
- **绘制依赖**：行变更比较也在后台执行，先跳过未变化的前后缀，避免局部编辑为全部逻辑行分配两份字符串列表。单个超长 ASCII 行的字数增量计算只检查编辑两侧的固定上下文。

## 复现基准

```sh
cargo build --release -p app --example editor_scalability
python3 scripts/benchmark-editor.py > editor.csv 2> editor-rss.csv
python3 scripts/benchmark-editor.py --sizes 1 10 --fixtures dense > dense.csv 2> dense-rss.csv
```

默认矩阵为 1、10、100 MiB × ASCII 极长单行、ASCII 日志、中文、Emoji（含 ZWJ、国旗和组合字符）、CRLF 日志。每个文件大小和场景使用独立进程，统一用 `benchmark.c` 文件名确保实际执行 LSH。依次测量首屏高亮、末尾高亮、软换行、搜索、单次编辑后的重排与行标记。普通搜索使用不存在的查询，另用密集匹配场景检查匹配缓存的内存上限。

`request_ms` 是调用返回前的主线程耗时；`total_ms` 包含后台完成与 1 ms 轮询间隔；`extra_peak_heap_mib` 是相对操作开始时已存活分配的峰值增量。堆分配计数包含 Rust 分配器的请求大小，不包含分配器保留的空闲内存及线程栈。Linux `VmHWM` 则记录整个进程（包括打开文件）的峰值 RSS。文件打开在各操作计时之前完成；这些数字不是磁盘加载时间或完整终端帧时间。

## 实测

2026-10-13，Linux x86_64、AMD EPYC 9V74、Rust 1.99.0，release 构建。以下为一次运行的观测值，不设易受共享机器负载影响的耗时 CI 门槛。

| ASCII 极长单行 | 搜索主线程请求（ms） | 搜索完成（ms） | 搜索额外峰值堆（MiB） |
| --- | ---: | ---: | ---: |
| 1 MiB | 0.137 | 2.288 | 0.124 |
| 10 MiB | 0.179 | 4.463 | 0.128 |
| 100 MiB | 0.135 | 25.403 | 0.128 |

| 100 MiB 场景 | 换行请求（ms） | 换行完成（ms） | 编辑及重排请求（ms） | 编辑及重排完成（ms） | 全进程峰值 RSS（MiB） |
| --- | ---: | ---: | ---: | ---: | ---: |
| ASCII 极长单行 | 0.018 | 3.235 | 3.067 | 6.775 | 216.5 |
| ASCII 日志 | 0.048 | 860.124 | 0.434 | 398.413 | 277.8 |
| 中文 | 0.039 | 3784.134 | 0.361 | 254.921 | 217.0 |
| Emoji | 0.059 | 3591.546 | 0.345 | 312.699 | 263.6 |
| CRLF | 0.042 | 755.571 | 0.340 | 311.711 | 274.0 |

10 MiB 密集场景包含 5,242,880 个匹配，交互缓存仍只保留 512 个位置；搜索额外峰值堆为 0.167 MiB，完整计数耗时 1.39 秒，主线程请求耗时 0.110 ms。

首轮跳转到 100 MiB 文件末尾的 LSH 状态恢复最多耗时约 11.1 秒，发生在后台。行数索引和全局行标记仍是多行文本的主要内存成本：本矩阵编辑/重排阶段最高额外峰值堆为 119.7 MiB；这里同时包含后台行变更比较。


原始数据见 [完整矩阵](benchmarks/editor-scalability.csv)、[峰值 RSS](benchmarks/editor-scalability-rss.csv) 和 [密集匹配](benchmarks/editor-dense.csv)。

## 明确保留的边界

- 任意正则表达式可能跨越无限长范围，仍在后台构造一份连续字符串，保留原有跨行、锚点和捕获组语义；已经移除其字素偏移数组。一次正则引擎调用内部不能立即取消，取消在它返回后生效。
- LSH 接受连续逻辑行。遇到超过 256 KiB 的逻辑行时，该行及后续内容保持无语法着色，避免复制巨大行或用未知解析状态错误着色；文本仍然可读、可编辑、可搜索。
- 精确的换行总行数和行变更标记仍需按逻辑行存储信息；首轮索引及远距离高亮也仍可能需要数秒后台计算。此改动不宣称所有缓存都与文件大小无关。
- 原有 Unicode 字数及显示宽度统计仍使用保守的逻辑行窗口；超长、无换行的 Unicode 文本编辑还可能受这些既有统计路径影响。当前矩阵的中文和 Emoji 场景含换行，极长单行场景是 ASCII。
- `SearchEngine::find_all`、`find_all_rope` 和全文高亮工具接口仍会按调用方要求返回全部结果；交互 UI 已改用后台视口/分页接口。

## 回归检查

```sh
cargo test -p app
cargo test -p shell --lib editor
cargo test -p shell --test editor
cargo test -p ui --test editor
cargo check --workspace --all-targets --all-features --locked
python3 scripts/check-localization.py
```

`editor_scalability` 覆盖分块与连续搜索结果等价、部分字素拒绝、跨块国旗、密集分页和循环导航、过期任务、当前/全部替换预览、长 Unicode 行的换行参考映射，以及编辑、Undo、宽度变化后的缓存一致性。后台任务还测试了队列覆盖和所有者释放后的取消。Linux 与 Windows/macOS 工作流均包含这些回归入口。
