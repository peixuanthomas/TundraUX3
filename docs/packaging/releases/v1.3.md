> This file records the historical release behavior of v1.3. The current master branch has removed the old Linux PAM integration and instead attaches to a normal system user. See the [Linux runtime notes](../linux/README-LINUX.txt) for current installation and update methods.

TundraUX3 **V1.3** includes the following updates since the previous stable release, **v1.2** (2026-09-07). The release tag is `v1.3`; the Cargo workspace, internal crates, and Linux packages all use version **1.3.0**.

## Added

- **RPM packages for Fedora-family distributions:** added an x86_64 `.rpm`, built natively and installation-tested on Fedora 43. It includes Shell, CLI, default resources, a desktop entry, licenses, and a PAM configuration adapted to Fedora's `system-auth`. The RPM automatically declares binary library dependencies, and PAM configuration upgrades preserve local changes.
- **Spring interface style and animations:** the main interface uses consistent card spacing, gentle entrance effects, and damped spring animations for update progress and system-usage bars. Existing theme, animation-speed, and reduced-motion settings are retained, with a compact layout for small windows.
- **Interactive UI style previews:** added `tundra-cli debug view-ui-style [1|2|3]` to compare Glacier, Tea, and Spring and try their lists, inputs, dialogs, and animations. Previews do not save settings.
- **Editor C syntax highlighting:** `.c` / `.h` files support highlighting for keywords, strings, characters, numbers, comments, and preprocessor directives. Default file associations expand to text formats including JSON, TOML, YAML, INI, XML, and CSV; existing custom associations remain unchanged.
- **System Status overview and editing:** the standalone System Overview shows CPU, memory, storage, battery usage, network and temperature trends, uptime, and major processes. Adding a widget from the right-click menu enters edit mode, with selection borders, editing hints, and reduced-motion support.
- **Live update feedback:** downloads and compilation show continuous progress and activity information, making it easier to tell whether a long build is still running.

## Fixed

- **Failed update checks:** if a GitHub API check fails, update information can be retrieved through Git instead.
- **Rust toolchain not found under Linux sudo:** the update workflow can find the calling user's installed default Rust toolchain, avoiding reliance solely on root's PATH / rustup environment.
- **Source updates using temporary memory-backed filesystems:** source-update compilation runs in a disk cache directory instead of memory-backed temporary directories such as `/tmp`.
- **Self-updates overwriting local resources:** updates replace only the Shell and CLI programs, preserving default themes, custom themes, and user data. A new update helper using protocol v2 prevents the old helper from continuing to require resource replacement. Update records using the old protocol are explicitly rejected, and original files are preserved.
- **Truncated update-confirmation button labels:** button width is calculated from the complete label.
- **Inconsistent Explorer toolbar and keyboard behavior:** added missing shortcut hints, restored Left/Right navigation back and forward, and unified refresh, sorting, options, and trash actions.
- **Hard-to-distinguish scrollbar thumbs:** adjusted the thickness of the thumb and track to make the thumb clearer.
- **ANSI terminal accent colors being changed:** preserves the user's configured ANSI hue and normal/bright choice; the focus color follows the accent color.

## Changes and compatibility notes

- Removed Launcher's reapproval button and action.
- System Status no longer shows Diagnostics / Logs / Incidents buttons at the top right; they remain accessible through `H` / `L` / `I` or dashboard widgets.
- The Fedora RPM build and installation-validation baseline is **Fedora 43 x86_64**. Other Fedora derivatives must satisfy the dependencies declared by the RPM. This package is not claimed to be a verified universal package for RHEL / CentOS / Rocky / AlmaLinux.
- In-application self-updates still compile from source and require a local Rust toolchain. Package versions in Linux package managers must be updated by installing a newer `.deb` / `.rpm`.

## Download and installation

| File | Platform |
| --- | --- |
| `TundraUX3-v1.3-windows-x64.zip` | Windows x64 |
| `TundraUX3-v1.3-macos-universal.tar.gz` | macOS Intel + Apple Silicon Universal |
| `TundraUX3-v1.3-linux-x86_64.tar.gz` | Linux x86_64 portable package (built on Ubuntu 24.04) |
| `TundraUX3-v1.3-linux-amd64.deb` | Debian / Ubuntu amd64 |
| `TundraUX3-v1.3-fedora-x86_64.rpm` | Fedora-family x86_64 (built on Fedora 43) |

Each platform includes a `.sha256` checksum file. After downloading the appropriate package and checksum file, run `sha256sum -c <filename>.sha256` (use `shasum -a 256 -c` on macOS).

Install on Fedora:

```console
sudo dnf install ./TundraUX3-v1.3-fedora-x86_64.rpm
```

Install on Debian / Ubuntu:

```console
sudo apt install ./TundraUX3-v1.3-linux-amd64.deb
```

After installation, run `tundra-shell` from a real terminal, or use `tundra-cli debug doctor` to check the runtime environment.
