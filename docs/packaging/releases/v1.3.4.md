TundraUX3 **V1.3.4** includes improvements to the screen keyboard, Linux system management, AutoAdmin (AA) task control, the command line, and file handling since v1.3.3. The program and all workspace packages use version **1.3.4**.

## Main updates

- **Screen keyboard:** running AA dialogs and embedded Command Line add a screen-keyboard entry point, supporting QWERTY, Shift, Tab, CapsLock, arrow keys, common key combinations, and clipboard operations. Opening it rearranges the content area, prioritizing retention of the AA window. Added highlighting for physical key presses and improved key colors, animations, and Chinese/English descriptions. Other application forms are not yet integrated; external terminals can still preview it with `tundra-cli debug screen-keyboard`.
- **Arch Linux package management:** added pacman installed-package lists, search, details, updates, and modification operations. Installation and upgrades refresh repositories and upgrade the full system to avoid partial upgrades. AUR builds and helpers are not provided. Added entry points for software sources, configuration-file conflicts, package-manager status, and failure handling, and restored navigation between package lists and details.
- **System configuration editor:** opens supported system configuration files in the existing editor, with validation, authorized saves, backup comparison, and restoration, while also checking for external file changes. Service definitions, software sources, and automatic-mount configuration can be edited through this entry point. Saving configuration does not start services or mount disks immediately by default.
- **More Linux management operations:** services add configuration, dependency, and ordering views, plus drafts for new services and templates. Processes add inspection of files, ports, I/O amounts, and associated services. Disks add health, file-count capacity, automatic-mount drafts, and locating space-scan results. Wi-Fi supports password connections, result verification, and recovery on failure; network diagnostics provides step-by-step results. Specific features depend on system tools, services, and permissions.
- **Full account management:** user management moves to Launcher and adds account lookup by name, groups, login shells, SSH public keys, and expiration operations. Remote accounts are read-only; when AccountsService is missing, supported fixed system tools fill the gaps. All modifications still require actual system authorization.
- **AA authorization and task control:** unifies dialog styles and animations. The foreground window remains visible while a task runs, and background tasks reopen it when they need a password or confirmation. Supports requesting termination of the current task, with another explicit confirmation required to force-stop it after a wait timeout. Automatic approval does not bypass system authentication or automatically answer installation prompts. Strengthened isolation between the current Shell authorization session and elevated tasks, and fixed dialogs not closing after rejection and authorization timeouts after sudo exits.
- **Operations CLI:** adds service, process, package, network, disk, account, configuration, and task commands, with structured results, task IDs, and explicit exit statuses. Improves settings, help, diagnostics, and Chinese/English operation flows.
- **Command line and file management:** REPL executes system commands by default; UX commands use the `/` prefix. Command Line can open in Explorer's current directory. Fixed prompt colors, spacing, and cursor position, and completed key-combination input from Windows Terminal to WSL. Returning prompts for confirmation and cleans up the current command line's child processes to avoid leaving descendants behind. Fixed crashes caused by terminal paste and provided clearer crash information.
- **Lists, navigation, and status messages:** unifies list actions and sortable column headers, placing common management actions at the bottom right with their actual shortcuts. Clicking the status bar opens the full message for reading and scrolling. Fixed user-management return destinations, clicking outside Explorer menus to close them, and multiple-selection highlighting; Toast now follows global border settings.
- **Pages and background tasks:** each opened page instance keeps its own selection, form, and scroll position, and returning restores the original page. Closing a page with a task offers continuing in the background, canceling and closing, or staying on the page. Old task results are not written into reopened pages. Dialog ordering and input focus are unified. Update preparation supports cancellation and preserves errors and related directories if cleanup fails.
- **Performance and maintenance:** subprocess output readers wait for output or exit notifications. Reduced allocations when reading file-log tails, reused directory-scan information, and limited concurrently open directories. Document fingerprints use a versioned XXH3 format, with buffered writes. Added repeatable performance checks and result documentation. Split AA and terminal runtime code and organized modules and documentation by function.

## Download and installation

| File | Platform |
| --- | --- |
| `TundraUX3-v1.3.4-windows-x64.zip` | Windows x64 |
| `TundraUX3-v1.3.4-macos-universal.tar.gz` | macOS Intel + Apple Silicon Universal |
| `TundraUX3-v1.3.4-linux-x86_64.tar.gz` | Linux x86_64 portable package (built on Ubuntu 24.04) |

Each platform includes one SHA-256 checksum file, for a total of six attachments. Linux provides only a portable package, with no DEB or RPM packages.

```console
tar -xzf TundraUX3-v1.3.4-linux-x86_64.tar.gz
cd tundraux3-1.3.4-linux-x86_64
./tundra-shell
```

Keep `tundra-shell`, `tundra-cli`, and the `assets` directory together. On Linux, also keep `tundra-installation.json` in the same directory. Packages for all platforms include Chinese and English resources. For everyday Linux use, run as a normal system user and follow the interface prompts to authorize operations that need additional permissions.

Linux is the primary target platform. Windows and macOS are mainly for exploring the interface and interactions and do not provide the same Linux system-management features. The macOS package contains both Intel and Apple Silicon architectures; it is neither developer-signed nor notarized by Apple.

## Build and release

This version is compiled, packaged, and published by the `Publish V1.3.4 release` GitHub Actions workflow. The release process does not run the test suite. Versions and tags are checked before release, and attachment counts and SHA-256 checksums are checked after upload.
