# TundraUX3

Linux 时钟统一跟随系统时间和时区，已有配置同样适用。“区域与时间”通过地图选择系统时区，并直接设置系统自动校时和服务器；“操作系统设置”保留主机名。文件属性支持多选权限与归属修改，递归执行前预览实际范围。

“应用设置”把文件管理器和编辑器放在左侧列表中，右侧显示当前应用的选项。

设置页最左侧大类由 Tab/Shift+Tab 切换，上下键选择项目，左右键只用于在应用列表与其设置之间切换焦点；回车或空格切换开关。数值项用回车或点击打开弹窗，在弹窗内用左右键移动光标、直接输入数字或点按减号／加号调整数值，回车确认、Esc 取消。AA 策略和屏幕超时保留各自的预设选项，通过选择弹窗确认。

输入弹窗以强调色和闪烁光标显示当前栏目；上下键切换栏目，左右键移动输入位置。

**只用终端，也能直观地操作设备。**

[English](../README.md) | 简体中文

TundraUX3 希望让用户在没有图形桌面、只有终端的环境中，也能方便地操作设备。它把菜单、按钮、列表、表单和系统信息带到终端里，让常用功能更容易找到、操作，不必为每项任务记住命令。

项目有两个重点：**面向 Linux 的实用系统操作**，以及**键盘、鼠标、触摸屏三者都能独立使用**。每种输入方式都应能单独完成操作，让用户根据设备条件选择。

TundraUX3 使用 Rust 编写，基于 Ratatui 和 crossterm。目前仍在积极开发中，部分操作流程和系统功能尚未完成。

## 平台定位

| 平台 | 用途 |
| --- | --- |
| **Linux** | 主要目标平台，用于在只有终端的环境中操作设备和管理系统。 |
| **Windows** | 支持 WinGet 软件包管理，其他系统控制仍以体验界面和交互为主。 |
| **macOS** | 体验界面和交互设计，支持通过 Homebrew 管理 Formula 和 Cask。 |

系统管理功能主要面向 Linux 开发。Windows 通过 WinGet、macOS 通过 Homebrew 管理软件包，其他系统控制不承诺提供与 Linux 同等的功能。可用的操作取决于已安装的工具、正在运行的服务，以及当前用户的权限。

## 可以做什么

- **空闲时显示天气：**“设置 → 系统”可选择永不、30 秒或 1/2/5/10/30 分钟，默认 5 分钟。按键或点按返回原页面，已登录时无需再次输入密码。

- **让 agent 操作界面：**在“设置 → 系统”开启外部 CLI 控制后，用 `tundra-cli ui` 读取运行中的界面树和文字画面，模拟点击、拖动、滚动或输入。仅限本机同一操作系统用户连接，详见 [CLI 控制](../crates/cli/docs/ui-control.md)。

- **管理 Linux 设备：**查看和控制服务、进程，管理软件包，配置受支持的网络连接，查看磁盘和挂载点。服务、进程和计划任务支持 Shift+点击、Shift+Enter 逐项多选和批量操作，F1 查看说明。
- **浏览软件包：**默认打开已安装，Tab/Shift+Tab 循环切换已安装、更新、搜索，↑/↓ 移动当前位置；Shift+点击或 Shift+Enter 逐项选中、取消，安装、卸载和更新处理全部已选包，授权窗口列出包名。F1 查看多选说明；展开详情后用四个方向键滚动内容。
- **管理 macOS 软件包：**通过 Homebrew 搜索、安装、卸载和升级 Formula、Cask，原生确认与密码在任务终端输入，详见 [Homebrew 支持](../crates/platform/docs/homebrew.md)。
- **管理 Windows 软件包：**同一个软件包页面通过 WinGet 搜索、安装、卸载、升级单个软件或全部升级，使用 `winget` 软件源。系统需要 App Installer 和已初始化的软件源，详见 [Windows 软件包](../crates/platform/docs/windows-packages.md)。
- **找到页面操作：**常用按钮位于右下方，主操作使用强调色，危险操作使用危险色。按 F1 或点击标题栏帮助按钮查看本页快捷键。
- **看清页面层次：**鼠标和触屏打开整页、弹窗、菜单时，边框从入口按钮逐渐放大，关闭时缩回同一个按钮；实体键盘操作立即完成。详情和屏幕键盘保留原有动画，设置支持整体速度、各阶段时长、恢复默认及减少动态效果。
- **管理端口和登录：**查看监听端口及所属进程，管理 UFW/firewalld 放行规则，修改 SSH 设置后在新连接中确认保留。
- **管理定时任务：**按“做什么、何时执行、检查并创建”选择服务重启、软件包更新或脚本；支持每天、每周、单次执行、未来时间预览，以及已有任务的编辑、停用和恢复。
- **找回操作结果：**启动器中的“任务”列出运行状态、输出和所属功能，重启后仍能查看历史；配置备份支持筛选、分页、保留和清理预览。
- **查看和恢复配置：**按操作查看原件、时间和差异，恢复配置、账户和用户组；密码以受保护的哈希保存，不在界面展示。
- **处理文件：**浏览目录并执行文件操作；编辑器提供语法着色、查找与替换、软换行和 JSON 格式化，F8 可切换到随包提供的真实 Vim，右上角显示“VIM模式已启用／未启用”，启用时使用彩虹色，并默认打开 106 种源码和配置后缀。
- **打开工具：**在内置命令行运行 TUI，或选中启动器的外部程序，通过“运行设置 F4”保存嵌入终端、参数和工作目录。支持增强键盘及 Kitty、Sixel、iTerm2 图片；纯文字终端使用字符色块预览。关闭终端时清理其进程树。
- **了解系统运行情况：**查看系统状态、资源使用、日志、通知和诊断信息。
- **调整使用体验：**选择英文或简体中文、调整外观，以及使用时钟和天气应用。

具体支持的操作和所需条件见 [Linux 系统管理](../crates/platform/docs/linux-management.md)。

Vim 模式显示 Vim 自己的终端界面，包括 Visual 模式、次数、寄存器、宏、窗口、命令行和 `:help`；`Ctrl+W` 处理 Vim 窗口。F8 返回普通编辑器，不自动保存文件，再按 F8 继续原 Vim 进程及其已有状态。`:w`、`:wq` 等文档保存仍使用 Tundra 既有的保存任务和受保护配置检查；`:q!` 按 Vim 规则放弃修改。具体操作见[编辑器说明](source-editor.md#真实-vim-模式)。

开启 Vim 模式时若缺少引擎，编辑器会下载本项目发布的对应预编译包，弹窗显示进度并支持取消，安装成功后自动继续。Windows、Linux 和 macOS 引擎使用同一个固定 Vim 版本。

## 键盘、鼠标或触摸屏

三种输入方式均可独立使用，是项目的核心设计要求：

| 输入方式 | 预期体验 |
| --- | --- |
| **仅用键盘** | 使用按键和快捷键切换控件、选择操作、输入文字和切换页面。 |
| **仅用鼠标** | 通过可见的按钮、菜单、选择框和滚动条操作，不依赖键盘快捷键。 |
| **仅用触摸屏** | 通过点按控件和拖动滚动条操作，无需实体键盘或鼠标。 |

鼠标和触摸操作需要终端转发相应事件。软件包、服务、进程、定时任务和文件管理提供可点按的“选择多项”、勾选框和已选数量。屏幕键盘覆盖内置文字输入，包括首次设置、登录、账户、设置弹窗、普通编辑器和查找替换、文件名及路径；提交和取消按钮始终留在键盘上方。AA 和内嵌命令行继续共用同一键盘。真实设备的验证情况见[本轮验收记录](operations-usability-validation.md)，详细操作见[键盘输入](../crates/shell/docs/session.md#aa-与命令行的屏幕键盘)。

点击底部状态栏的消息区域，可在弹窗中阅读完整文本。长消息会换行，并支持滚动；时钟仍保留独立的点击操作。

## 快速开始

请使用交互式终端，默认界面至少需要 **108 列 × 20 行**。内置命令行等应用需要更多垂直空间。鼠标和触摸支持取决于所用终端。

### 使用 Linux 便携包

1. 从 [GitHub Releases](https://github.com/peixuanthomas/TundraUX3/releases) 下载 Linux x86_64 便携压缩包。
2. 解压到属于当前普通 Linux 用户的目录。
3. 将 `tundra-shell`、`tundra-cli`、`assets/`、`vim/` 和 `tundra-installation.json` 保留在同一目录中。
4. 在解压目录打开终端并运行：

```sh
./tundra-shell
```

检查运行环境：

```sh
./tundra-cli doctor
```

Linux 版本使用启动程序的系统账户及其权限。日常使用普通用户运行；需要额外权限的操作，会通过相应的系统工具请求授权。退出 TundraUX3 会关闭应用并返回终端。

Linux 版本以便携包发布。在**设置 → 更新**中，**正式版（Release）**下载稳定的便携版本，**测试版（Beta）**使用本机 Rust 工具链编译 `master` 的最新提交。程序自更新要求便携目录属于当前用户且可写，并保留个人数据和主题。依赖与更新细节见 [Linux 运行说明](packaging/linux/README-LINUX.txt)。

从使用更新协议 v2 的旧版首次升级时，需完整解压一次新便携包。旧版更新器会拒绝新协议 v3；新协议同时部署随包 Vim 运行目录。

### 从源码构建

安装 **Rust 1.95 或更新的稳定版**工具链、Cargo 和所用平台需要的构建工具。在仓库根目录执行：

```sh
cargo build --locked -p shell -p cli
python3 scripts/build-vim.py --output target/debug/vim
cargo run --locked -p shell --bin tundra-shell
```

更新源码后也要重新构建 Shell 和 CLI；`packaging/vim.json` 变化时重新构建 Vim。单独运行 `cargo run -p shell` 不会重新构建 Command Line 使用的 `tundra-cli` 可执行文件。

Vim 构建步骤显式下载并编译固定的上游版本，普通 Cargo 构建不会下载 Vim。该步骤需要 Python 3.12 或更新版本及本机 C 构建工具，Windows 可使用 `python`。构建依赖、发布路径和离线归档用法见[随包 Vim](packaging/vim.md)。`TUNDRA_VIM` 可指定其他兼容的完整 Vim 可执行文件；隔离测试可设置 `TUNDRA_VIM_CLEAN=1`，跳过个人 Vim 配置和插件。

查看配套命令行工具：

```sh
cargo run --locked -p cli --bin tundra-cli -- --help
cargo run --locked -p cli --bin tundra-cli -- doctor
```

请同时构建这两个包：Shell 的内置命令行和 Linux 管理任务会使用配套 CLI。构建、测试和打包细节见 [技术文档](README-TECHNICAL.md)。

## 当前限制

- 项目重点是终端界面。启动图形应用或调用桌面服务的功能，仍需要对应的应用或服务；在只有终端的会话中，这些功能可能不可用。
- Linux 管理功能各有运行条件，例如服务管理需要 systemd，软件包管理需要受支持的发行版工具。缺少组件时，界面会说明原因。
- 网络操作位于“启动器 → 网络”。设置中不可用的声音、显示、Wi-Fi 和蓝牙页面已移除；用户管理移至“启动器 → 用户管理”。
- 各种输入方式的操作覆盖和真实设备上的表现仍在完善，项目尚不承诺支持所有终端、触摸屏或 Linux 发行版。
- Vim 使用终端界面。Linux 有真实 PTY 和外部 UI 控制回归，Windows 有真实 ConPTY 保存与编码回归；macOS 的构建和运行时检查仍需在对应 CI runner 执行，不能以其他平台结果代替。
