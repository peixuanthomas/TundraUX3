# 任务与执行历史

标题栏的“任务”按钮和启动器打开同一页面。列表显示名称、状态、开始时间和所属功能；搜索和状态筛选可缩小范围。每批显示 50 条，可查看输出、返回所属页面或请求取消；清理位于“更多”。当前页面还存在时返回原实例，关闭后重新打开所属功能，不重复执行原操作。

等待批准、等待输入、运行、取消中、成功、失败、已取消和待核实分别显示。调用 systemd 成功只表示已提交启动请求；每次实际执行的结果以独立历史为准。取消后必须等工作线程和进程树停止，已完成的修改不会自动撤销。

普通页面历史位于当前用户数据目录的 `task-history/`。Linux 授权助手按发起账户写入 `/var/lib/tundraux3/task-history/UID/`；定时任务按执行账户写入 `/var/lib/tundraux3/scheduled-results/UID/history/`。页面、授权助手使用同一稳定编号，列表合并重复结果，优先显示系统归档。新建定时任务的每次执行使用 systemd 独立执行编号；关闭 Tundra 期间仍能记录开始、结束和输出。

输出逐块写盘，每次读取至多 64 KiB，可向前、向后翻阅。摘要和输出跨重启保存；不写密码、按键或粘贴输入，不归档配置查询正文。输出保存失败会标明不完整；重启后核对本次开机标记、进程编号和启动时间，不能确认的结果显示待核实，不自动重跑。

历史只手动清理。页面显示总占用及各来源占用；预览列出任务名称、时间、结果和释放空间，删除前重新核对相同记录。运行中的记录不可删除。系统归档与个人副本分开清理：删除系统归档后，保留的个人副本可能重新显示，名称中注明来源。其他执行账户的历史可授权读取，其清理按钮保持禁用；当前账户及 root 自有记录分别沿原权限路径处理。

Linux 的系统记录读取需要显式授权。自动刷新更新个人历史并保留上次系统记录；点击刷新后重新授权读取系统变化。未获取系统记录时，页面不能代表所有系统任务的完整历史，标题栏只统计当前已知任务。输出中的系统工具诊断保留原文。

自动回归覆盖输出分段、重复编号、进程编号复用、重启、待核实状态、取消收尾、写入失败和清理版本检查。实际执行结果与设备输入验收见[本轮验收记录](../../../docs/operations-usability-validation.md)。
