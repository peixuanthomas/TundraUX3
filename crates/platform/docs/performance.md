# platform 性能优化与复测

本轮按进程等待、日志分配、文档指纹、目录读取与句柄控制的顺序实施。上层仍使用原有的进程、日志、文档和目录接口；底层实现保留取消、文件身份、链接和挂载检查。

## 实现

- **进程等待**：Unix 用 `poll` 等待输出；Linux 额外使用 `pidfd`，让进程退出也能立即唤醒。旧内核或受限环境无法创建 `pidfd` 时仍可运行。已经读完的管道退出等待集合，避免空转。每轮读取量继续受限，等待最长 20 ms 后重新检查取消。Windows 持续有输出时直接读取，空闲时等待进程句柄，最长 20 ms。取消仍由原有进程组或 Job Object 停止本次启动的进程树。
- **日志分配**：先扫描最多 8 MiB 的日志尾部，只保存最后需要返回的行的位置，再创建日志对象。旧行不再创建事件、时间戳和路径字符串。保留坏字符统计、空行规则、字节偏移、8192 字符限制、过滤提示和取消检查。
- **文档指纹**：将逐字节 FNV 换成 `xxhash-rust` 的 XXH3-64；读取仍分块计算。写入增加 64 KiB 缓冲，合并编辑器产生的小块写入。写前和安装前的冲突检查、临时文件权限、`sync_all`、原子替换和父目录同步均保留。XXH3 仅判断文档是否变化，不替代安全用途的 SHA-256。
- **恢复记录**：新写入的草稿带有 `saved_content_hash_algorithm = "xxh3-64-v1"`。没有标记或标记未知的草稿仍可恢复正文，但旧指纹不会绑定原文件；用户需要另存为。不会删除、重写或丢弃旧草稿。
- **目录读取**：Linux 的普通文件只查一次属性，直接复用执行权限信息；ELF 和脚本头合并为一次文件打开。读取文件头使用不跟随末级符号链接、非阻塞打开。普通文档即使带执行权限也仍走正常打开流程。
- **磁盘扫描**：用一次 `statx` 查询取得文件类型、大小、块数、设备、文件编号和挂载编号；缺少必要字段时明确失败。目录游标直接拥有已打开的句柄，不再通过 `/proc/self/fd` 再开一份。逐个进入子目录，只保留当前目录及祖先，离开即关闭。目录深度上限为 `min(256, max(1, RLIMIT_NOFILE - 32))`，到达上限明确报错，不伪装成完整结果。硬链接去重、挂载隔离和进入目录前的身份复查仍保留。

使用成熟的 Rust 实现和系统接口已经消除了本轮主要开销，没有新增 C/C++ 构建依赖。XXH3 的算法与处理器优化说明见[上游实现](https://github.com/DoumanAsh/xxhash-rust)。

## 性能复测

运行：

```sh
CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 cargo run --release --locked -p platform --example performance_probe
```

程序只操作临时目录，通过实际公开接口测试，包含真实进程身份查询、文档安全检查和保存同步。每项先预热一次，再取 7 次测量的中位数；同时统计 Rust 分配和重新分配次数。计数器本身有开销，不计系统 C 库内部分配。日志样本是 9 MiB 文件、读取最后 8 MiB、返回 200 条记录；目录样本为 3000 个普通文件。文档读取使用热缓存，不能代表冷盘或远程文件系统性能。

比较基准为 `cf3592e`。从该提交导出临时源码副本，将当前的 `examples/performance_probe.rs` 放入同一路径，再用相同 release 配置构建；无需切换当前分支。测试机为 Intel Core Ultra 9 275HX，WSL2 Linux 6.18.33.1，Rust 1.98.0，样本位于原生 Linux 临时目录。

2026-10-11 实测：实现截止 `56928f8`。编译与测试结束后，用 `taskset --cpu-list 0` 将两个程序及其子进程固定到同一核心，按“优化前、优化后、优化后、优化前”顺序运行。下表范围是两轮各 7 次测量的中位数，单位为毫秒。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 等待并收集 4 MiB 进程输出 | 805.870–861.546 | 1.134–1.262 |
| 读取 8 MiB 日志尾部，返回 200 条 | 553.182–565.547 | 12.223–12.788 |
| 64 MiB 文档指纹，含文件读取 | 57.206–57.529 | 5.236–6.082 |
| 64 MiB 文档按 1 KiB 小块保存，含同步 | 108.130–111.699 | 38.148–38.684 |
| 列出 3000 个普通文件及打开策略 | 8.625–9.261 | 4.692–4.769 |
| 扫描 3000 个文件并生成结果 | 5.189–5.397 | 4.610–4.687 |

同一日志查询的 Rust 分配次数从 **4,976,297** 降到 **7,031**；扫描从 **53,952** 降到 **47,948**。目录列表的分配次数未变，收益来自少做属性和文件头查询。进程的巨大差异来自去掉每轮读取后的固定 20 ms 停顿，不能推广为所有程序本身都快几百倍。未固定核心时，扫描两轮结果范围仍有重叠，因此扫描的主要确定性收益是减少分配与限制句柄占用。

固定核心复测可先构建，再运行，避免把编译时间算进去：

```sh
CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 cargo build --release --locked -p platform --example performance_probe
taskset --cpu-list 0 target/release/examples/performance_probe
```

## 验证与限制

- WSL 完整测试：`CARGO_BUILD_JOBS=2 CARGO_INCREMENTAL=0 cargo test --workspace --locked`。
- Windows：`cargo +stable-x86_64-pc-windows-msvc test --locked -p platform -p app`。
- 目录扫描专项：`cargo test --locked -p platform management::disks::scan:: -- --include-ignored --test-threads=1`。绑定挂载测试使用独立用户和挂载命名空间，不修改主机挂载。
- 格式：`cargo fmt --all --check`；差异：`git diff --check`。

上述检查本轮均通过。扫描专项 8 项全部通过，含默认忽略的隔离挂载测试；完整工作区命令仍按项目默认保留其他被忽略的测试，不代表它们已执行。

专项覆盖同时读取两个管道、关闭管道后的取消与退出、日志截断和损坏字符、不同写入块大小、写入失败保留原文件、旧草稿读取、短文件头、符号链接、硬链接、绑定挂载、目录改名，以及低句柄限制下的宽目录和深目录。

WSL 的 Windows 共享目录在目录改名后可能让 `openat` 返回 `ENXIO`。已用原生 Linux 目录和共享目录分别复现：前者通过原句柄读到原文件，后者明确失败。扫描继续将打不开的条目计为不可用，不改用可能已被替换的路径绕过检查。macOS 实机行为、本机桌面交互和真实设备操作不属于上述自动测试的验收范围。
